
परिणाम लोकल zero-cost runtimes, live OpenRouter zero-price मॉडल, और provider
free-tier-eligible मॉडलों के बीच अंतर करते हैं। Free-tier उपलब्धता अब भी account,
region, quotas, और provider policy पर निर्भर करती है; Arka कभी भी paid मॉडल को
केवल इसलिए मुफ़्त नहीं कहता कि उसके पास एक free quota है। यह देखने के लिए कि खोजे
गए कौन-से लोकल या hosted विकल्प वास्तव में पहुँच योग्य हैं, `arka hybrid status`
का उपयोग करें।

## Model policy

`ARKA_MODEL_POLICY` `arka hybrid` और shared LLM fallback engine द्वारा उपयोग की
जाने वाली fallback chain को reorder करता है। यह providers को जोड़ता या हटाता नहीं
है; यह केवल यह बदलता है कि chain की कौन-सी side पहले चले (या केवल एक ही side को
रखे)।

| मान | व्यवहार |
| --- | --- |
| `local-first` (default) | पहले लोकल runtimes (Ollama, vLLM, LM Studio, Exo) आज़माएँ, फिर hosted providers। |
| `hosted-first` | पहले hosted providers आज़माएँ, फिर लोकल runtimes। |
| `local-only` | Hosted providers को पूरी तरह skip करें। Offline या private runs के लिए उपयोगी। |
| `hosted-only` | लोकल runtimes को पूरी तरह skip करें। जब लोकल मॉडल धीमे या अनुपलब्ध हों, तब उपयोगी। |

```bash
export ARKA_MODEL_POLICY=hosted-first
arka hybrid status

# या केवल एक command के लिए set करें
ARKA_MODEL_POLICY=local-only arka chat "summarize this"
```

Policy आपकी मौजूदा fallback config के बाद लागू होती है: `LLM_AUTO_FALLBACK`,
`AI_PREFERRED_PROVIDER`, `AI_PREFERRED_MODEL`, और `llm-skill-models.json` में
per-skill routing अब भी शुरुआती candidate list चुनते हैं। इसके बाद policy उस list
को filter और reorder करती है। अज्ञात मान `local-first` पर fall back होते हैं।
