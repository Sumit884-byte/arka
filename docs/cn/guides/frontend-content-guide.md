# 前端内容指南

在设计或审查任何面向用户的界面、落地页或应用内文案时使用本指南。
前端是为**使用产品的人**服务的，而不是用来记录产品是如何构建的。

---

## 黄金法则

**展示结果、操作和信任信号。隐藏实现细节、组织结构和运维信息。**

如果一句话只有工程师、填写资助申请表的创始人或阅读代码仓库的人才能看懂——它就不应该出现在默认 UI 中。

---

## 在前端展示

| 类别 | 示例 |
|----------|----------|
| **产品能做什么** | 一句话价值主张，用通俗语言描述功能带来的好处 |
| **用户下一步能做什么** | 主要 CTA，带有明确下一步的空状态 |
| **影响用户的状态** | “消息已发送”、“正在同步…”、“上传失败——请重试” |
| **用户必须提供的输入** | 邮箱、密码、偏好设置、用户拥有的内容 |
| **信任与安全（与用户相关）** | 隐私摘要、用通俗语言说明的数据保留期限、支持联系方式 |
| **定价（如果你在销售）** | 套餐、限额、试用期——只展示会影响用户付费或所得的内容 |
| **无障碍** | 标签、与字段关联的错误、焦点顺序、对比度——这些不是可选项 |

### 良好模式

- “连接你的 LinkedIn 账户，即可在一个地方发送消息。”
- “我们将你的凭据存储在本设备上。”
- “今天已安排 3 条消息。”

## 不要在前端展示

| 类别 | 为什么保留在内部 |
|----------|------------------------|
| **技术栈** | React、Next.js、Python、Selenium、Ollama、Postgres——这些不是用户选择的 |
| **营利与非营利身份** | 组织的税务身份无关紧要，除非产品*本身*就是筹款或资助 |
| **内部工具** | Arka、Cursor、PrivateGPT、SigNoz、CI、Docker、`.env` |
| **架构与 API** | 微服务、webhooks、队列名称、模型 ID、提供商回退 |
| **开发/运维健康横幅** | “数据库已连接”、“API 正常”、“Redis 运行中”、“已加载 8 篇帖子”——基础设施检查应放在日志中，而不是界面上 |
| **业务分类** | “B2B”、“黑客松项目”、“副业项目”、面向投资人的收入模式 |
| **原始错误与堆栈跟踪** | 在支持流程中可以出现日志 ID；主 UI 上绝不显示堆栈跟踪 |
| **安全内部细节** | 密钥名称、vault 路径、OAuth 客户端密钥、令牌轮换策略 |
| **合规样板文字（未经筛选）** | 完整法律实体名称、DUNS、内部政策 ID——改为外部链接 |

### 不良模式（删除或移至文档/管理后台）

- “由 Selenium + Groq + Arka agent hub 驱动。”
- “这是一个非营利研究原型。”
- “后端：Railway 上的 FastAPI，前端：Vite。”
- “ROUTE_MODE=symbolic，已启用 LLM 回退。”
- “数据库已连接 · API 正常 · 已加载 8 篇帖子”
- “Postgres 正常 · Prisma 已连接 · 缓存已预热”

**改用以下写法（或者除非用户需要采取行动，否则完全隐藏）：**

- “8 篇帖子已就绪”
- “ResearchFeed 已上线——浏览最新帖子。”
- 仅在失败时：“无法加载帖子。请稍后重试。”

## 灰色地带——仅在有意为之时展示

| 主题 | 何时可以出现 |
|-------|-------------------|
| **开源/许可证** | 如果你分发代码，可放在页脚或“关于”页面；一行简短说明，并链接到 LICENSE |
| **AI/自动化** | 如果用户必须知道内容由 AI 生成（披露法规、信任）——用一句清晰的话说明，不写模型名称 |
| **集成** | “使用 Google 登录”（用户操作），而不是“已配置 Google OAuth 客户端 ID” |
| **非营利/使命** | 如果使命就是产品，可放在营销网站的**关于**页面；不要放在应用界面或错误提示中 |
| **技术细节** | 开发者文档、`/docs`、README、管理控制台——绝不放在默认仪表盘上 |

---

## 逐屏检查清单

在发布页面或弹窗之前，请确认：

- [ ] 每个可见标签都在回答“*我*能做什么？”或“*我的*东西怎么了？”
- [ ] 不出现框架、库或基础设施名称，除非用户明确选择了开发者视图
- [ ] 不出现营利/非营利/融资/黑客松相关措辞，除非该页面是**关于**或**定价**页面
- [ ] 错误信息可操作（“请检查你的密码”），而非诊断式（“401 from `/api/v1/auth`”）
- [ ] 设置中暴露的是**用户选项**（语言、通知），而不是**部署配置**（API base URL）
- [ ] 空状态引导用户完成第一个操作，而不是解释系统内部如何运作
- [ ] 页脚/法律信息：链接到隐私政策和条款，而不是内部运维手册
- [ ] 不显示开发状态条（数据库/API/队列健康状况、“已加载 N 条记录”），除非该页面是管理控制台

## 文案模板

### Hero/落地页

**推荐：**“无需切换标签页即可发送个性化 LinkedIn 消息。”  
**避免：**“一个用于外拓增长的 Python 自动化技术栈（非营利 MVP）。”

### 设置

**推荐：**“LinkedIn 账户”、“每日发送上限”、“暂停自动化”。  
**避免：**“LINKEDIN_USERNAME 环境变量”、“ChromeDriver 路径”、“Arka 路由模式”。

### 错误

**推荐：**“无法登录。请检查你的邮箱和密码。”  
**避免：**“WebDriverException: chrome not reachable (Arka coding-tui baseline).”

### 关于（可选页面）

**推荐：**用一段话说明使命；链接到隐私政策；提供支持联系方式。  
**避免：**完整的技术附录，除非受众是开发者且页面标注为**面向开发者**。

### 状态/健康页面

**推荐：**“ResearchFeed 已上线”、“信息流和登录均可用”、“8 篇帖子可供阅读”。  
**避免：**“数据库已连接 · API 正常 · 已加载 8 篇帖子”——连接检查写入日志；只展示用户关心的结果。

## 面向 agent 和构建者

Arka 会在前端/UI 工作、coding-tui 计划以及
`frontend_loop` 截图审查中**自动**加载本指南（默认 `FRONTEND_CONTENT_GUIDE=1`）。可搭配
[Google DESIGN.md 指南](./google-design.md) 使用，以获取视觉 token 和布局规范。

可在 `~/.config/arka/.env` 中进行可选覆盖：

```bash
FRONTEND_CONTENT_GUIDE=1              # default on
FRONTEND_CONTENT_GUIDE_MODE=auto      # auto | always | off
```

需要时手动读取：

```bash
arka md_doc read docs/guides/frontend-content-guide.md
```

通过 MCP，`arka_markdown` 接受别名 `frontend-content-guide`（内置文案政策）。

实现 UI 时：

1. 不要把技术栈、营利/非营利身份或内部工具名称粘贴到用户可见的文案中。
2. 将技术说明放在代码注释、README 或内部文档中——而不是按钮或提示消息中。
3. 如果不确定，就在屏幕上少展示一些；通过链接提供深入内容。
4. UI 修改后运行 `arka ui-copy .` 以发现重复标签。
